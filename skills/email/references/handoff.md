# Handoff

Used to deliver. The email is finished; what is left is getting it into the user's hands in a form they can send as it is.

## Delivering

- The email goes in the reply, ready to copy. The approved card is the specification: delivering doesn't reword it.
- **Email:** the To and Cc line first (marked as a suggestion when the user didn't set it), then the subject line, then the body as plain text.
- **Slack, Teams, WhatsApp:** the message as it will be pasted, with only the formatting the channel renders; when the plan splits it, each message as its own block.
- **Letter:** the full text, with date and greeting where convention expects them.
- Outside the email, in a few lines:
  - **Before sending:** what the card says should happen first (a call, a word with someone, an attachment the email mentions, the moment to send).
  - What changed from the card, if anything.
  - Placeholders or `[TO CONFIRM]` markers still in the text.
  - The result of the cold reader, or "not run".
  - The one-line offer of a firmer or softer version, if it wasn't made yet.
- Don't hand over an email that still holds placeholders without saying so in the same line.
- The skill never sends, schedules or saves the message anywhere: sending is the user's act.
- When the answer comes, a follow-up is a new run with the thread as material.
