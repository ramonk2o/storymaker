# Handoff

Used to bring the delivery options with the results of the checks, and to deliver. The post is finished; what is left is getting it to the network, and to whoever designs a carousel, in a form that survives the trip.

## Choosing how to deliver
1. **Look at what this session can do right now** to deliver a post: plain text in the reply, an editable document, connectors to apps where the post will be scheduled or reviewed. Offer only what is actually available; never assume a tool exists.
2. **Present the viable options,** numbered, one line each with one pro and one con for this post, and recommend one. The post in the reply, ready to copy, always exists; if it is the only option, deliver it without listing options.

## Delivering
- The approved plan is the specification: moving the post to another place doesn't reword it.
- **Single post or caption:** plain text, ready to paste, with its character count.
- **Thread:** each post as its own block, numbered for the user's reference (the numbers go into the posts only if the voice uses them), each with its character count against the limit.
- **Carousel:** slide by slide, each with its words, its visual note and its alt text; then the caption. When a designer will make the slides, offer in one line a table with the same content to hand over.
- **Several networks:** one block per network, labeled.
- Image alt text whenever an image goes with the post.
- Outside the post, in a few lines: what changed from the plan, if anything; open items marked `[TO CONFIRM]` or placeholders still in the text; the platform figures used and where they came from; and the result of each check that applies, or "not run".
- The skill never publishes or schedules a post: publishing is the user's act. Save it as a draft when the session can and the user asks.
- Don't move a post that still holds placeholders or `[TO CONFIRM]` markers without saying so in the same line.
