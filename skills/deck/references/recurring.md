# Recurring decks

Used for periodic decks — monthly report, weekly status, committee, quarterly review — in the Opening, when the user brings a Recurring blueprint, and when delivering the first edition.

## First edition
After the build, deliver a **Recurring blueprint** for the user to keep (for example, in a project's files):

```
RECURRING BLUEPRINT — [name]
Audience · shift · format · duration
Deck type · arc
Storyline structure, with titles as molds ("[Metric] [rose/fell] X% vs. [reference]")
Visual concept · global rules · template/identity · build option
Data source for each slide
Update questions:
  - What changed since the last edition?
  - What is the central idea of this edition?
  - Which decision is needed now?
  - Any new data? Any slide that stopped mattering?
```

## Later editions
With the blueprint in hand, go straight to express mode.
- The Opening becomes one round with the update questions, and the proposal always brings a new central idea: the structure repeats, the message doesn't.
- The visual direction and the prototype are reused; they reopen only if the audience, objective or identity change.
- If the build option in the blueprint isn't available in this session, choose again as `handoff.md` says.
- Recurring decks tend to turn into a list of metrics; the stress-test round always asks what is news in this edition and what decision it calls for.
